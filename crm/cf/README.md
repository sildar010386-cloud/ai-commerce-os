# Bikas CRM (Cloudflare Worker + D1)

Своя CRM без claude.ai: вход по почте и паролю, заказы, контент-план, склад, прибыль, менеджеры. Работает на бесплатном тарифе Cloudflare (Worker + база D1). Страница открывается с телефона и с компьютера.

## Что нужно добавить в GitHub (один раз)

Репозиторий → Settings → Secrets and variables → Actions → New repository secret. Добавьте секреты:

| Секрет | Что это |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Токен Cloudflare: My Profile → API Tokens → Create Token → шаблон **Edit Cloudflare Workers** → Use template → «+ Add more»: **Account · D1 · Edit** → Account Resources: ваш аккаунт, Zone Resources: All zones → Continue to summary → Create Token. |
| `CLOUDFLARE_ACCOUNT_ID` | Номер аккаунта Cloudflare (Workers & Pages → справа «Account ID»). |
| `CRM_API_KEY` | Любая длинная случайная строка (30+ символов). Это ключ, которым публикации и воронка пишут в CRM. Никому не показывайте. |
| `CRM_ADMIN_EMAIL` | Ваша почта — по ней вы входите в CRM (например `you@gmail.com`). |
| `CRM_ADMIN_PASSWORD` | Ваш пароль для входа, **не короче 10 символов**. |
| `WA_TOKEN`, `WA_APP_SECRET`, `WA_VERIFY_TOKEN` | Необязательно. Для подключения WhatsApp через Cloud API (токен, секрет приложения, проверочное слово для вебхука). Без них раздел «Чаты» работает, но не получает и не отправляет сообщения через Cloud API. |
| `CONNECTOR_URL`, `CONNECTOR_KEY`, `CONNECTOR_MEDIA_HOSTS` | Необязательно. Для подключения номеров «по QR» через отдельный коннектор: адрес коннектора, общий ключ, список разрешённых хостов вложений через запятую. |
| `GH_DISPATCH_TOKEN` | Необязательно. Токен GitHub для кнопки «Опубликовать сейчас» прямо в CRM: Settings → Developer settings → Fine-grained tokens → доступ только к этому репозиторию, право **Actions: Read and write**. Без него кнопка открывает страницу GitHub, где нужно нажать «Run workflow». |

Один раз зайдите в Cloudflare → Workers & Pages и, если попросит, выберите имя поддомена workers.dev.

## Как развернуть

1. GitHub → Actions → **CRM deploy** → Run workflow.
2. Дождитесь зелёной галочки. В конце в журнале и на странице запуска будет адрес CRM.
3. Откройте адрес, войдите почтой и паролем из секретов `CRM_ADMIN_EMAIL` / `CRM_ADMIN_PASSWORD`.
4. Адрес CRM сохраняется сам (файл `crm/url.txt`), публикации и воронка начинают писать в CRM автоматически.

Повторный запуск безопасен: он обновит CRM, данные не трогает, второго админа не создаёт. Чтобы обновить CRM после изменений в коде, просто запустите деплой ещё раз.

## Как пользоваться

- **Меню → Менеджеры и доступы**: создать менеджера (имя, почта и пароль, которые вы ему придумали; передайте лично), отключить, сбросить пароль. Менеджер видит заказы, контент, остатки, номера WhatsApp и ссылку на оплату; прибыль, кассу, закупку и настройки не видит (закрыто на сервере).
- **Меню → Моя почта и пароль**: сменить свою почту и пароль.
- **Меню → Настройки**: номера WhatsApp, ссылка на оплату, шаблоны.
- **Акции «1+1» и «2+1»** (подарок — тот же товар): в карточке заказа выберите «Акция» и впишите «Оплачено, шт.»; «В подарок» и «Отправить всего» считаются сами (1+1: подарков столько же, сколько оплачено; 2+1: один подарок за каждые две оплаченные). Склад списывает отправленное количество (оплачено + подарок), касса и сумма — деньги, которые получены. В «Статистике» есть карточка «Акции», в «Прибыли» — отправлено / оплачено / подарено.
- **Расходы на товар** (Меню → Прибыль, у каждого товара; кнопка «Расходы» в Складе; видит только админ). «На 1 штуку»: закупка и прочее — умножаются на отправленные штуки вместе с подарками. «На 1 посылку (заказ)»: доставка Казпочтой и упаковка — один раз на заказ, один заказ = одна посылка. Раньше доставка и упаковка считались на штуку: числа остались, но теперь это расход на посылку. «Иные расходы» — свои строки (название, сумма, на штуку или на посылку, до 20). Комиссия — процент от суммы.
- **Меню → Склад**: добавьте товар (цену и остаток). Остаток уменьшается сам, когда заказ получает статус «Отправлен».
- **Чаты** (верхняя вкладка): переписка с клиентами из WhatsApp. Слева список (непрочитанные, поиск, фильтры «Таргет» / «Органика»), справа переписка и поле ответа. У каждого чата метка: «Таргет · товар (код)», «Органика» или «Старый» (клиент, который был до подключения). Метку можно поменять вручную. Кнопка «Оформить заказ» создаёт заказ из чата (имя, телефон, источник WhatsApp, таргет/органика, последнее сообщение клиента). Отвечать можно в течение 24 часов после сообщения клиента; если номер заблокирован, CRM скажет об этом, и ответить нужно с телефона или с запасного номера. На телефоне список и переписка — два экрана.
- **Меню → Настройки → Номера WhatsApp**: несколько номеров, у каждого статус (активен / заблокирован / выключен), способ подключения (по QR / Cloud API) и время последнего сообщения. Переключатель «Ссылки ведут сюда» выбирает номер, на который ведут общая ссылка `<адрес CRM>/wa` и ссылки `/wa/<код>`. Если основной номер заблокировали: отметьте его «заблокирован» и выберите запасной, реклама и лендинг останутся прежними.
- **Меню → Настройки → Таргет — товары и тексты**: для каждого товара короткий код и текст, который клиент отправит сам из рекламы или лендинга (ссылка `<адрес CRM>/wa/<код>` подставляет этот текст). По тексту или коду в скобках, например (A3), CRM понимает, что клиент из таргета и по какому товару. Видно клики по ссылке и число обращений.
- **Меню → Настройки → Подключение WhatsApp**: программа-подключение держит один номер как «Связанное устройство». Два способа. **«На этом компьютере (Windows)»**: кнопка «Скачать установщик для Windows» создаёт новый ключ (старый перестаёт работать, CRM спрашивает подтверждение) и скачивает `BikasWhatsApp-setup.cmd` (CRLF, адрес CRM и ключ вшиты; `POST /api/wa-server/windows-installer`, только администратор, `Content-Disposition: attachment`, `Cache-Control: no-store`); файл открывают двойным щелчком (Windows может показать «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае»), он ставит всё в `%LOCALAPPDATA%\BikasWhatsApp` без прав администратора; ноутбук должен быть включён, чтобы сообщения доходили до CRM (пока он выключен, WhatsApp хранит их). **«На сервере (Linux)»**: «Создать ключ подключения» показывает один раз готовый скрипт для сервера (Google Cloud: «Автоматизация» → «Скрипт запуска»; Oracle: Initialization script) с кнопкой «Скопировать скрипт»; новый ключ отключает старый. Пока ждёт привязки, показывается QR-код (WhatsApp Business → ⋮ → Связанные устройства → Привязать устройство). **«Переподключить на другой номер»**: номер заблокировали — нажмите, отсканируйте QR-код другим телефоном, и все ссылки `/wa`, `/wa/<код>` переключатся на новый номер. Подробности: `connector/README.md` (раздел «Windows (ноутбук)»). Шаблон установщика один: `connector/windows/setup.template.cmd`; в Worker он попадает через сгенерированный `src/connector_windows.js` (`node scripts/gen-windows-setup.js`, тест следит, чтобы они совпадали).
- **Голосовые и фото в чате** (для номера, подключённого через «Подключение WhatsApp»): кнопка микрофона записывает до 2 минут с прослушиванием перед отправкой (запись сразу переупаковывается в Ogg/Opus прямо в браузере, `public/ogg.js`, поэтому ffmpeg на компьютере с подключением не нужен), кнопка фото отправляет JPEG/PNG/WebP (больше 1,5 МБ сжимается сама; текст из поля ответа станет подписью). Статусы сообщений: в очереди, отправлено, доставлено, прочитано, ошибка. Если сервер не на связи, сообщение ждёт его (до 6 часов).
- **Контент**: статусы постов обновляются сами после каждой публикации; красный «ошибка» — публикация не прошла.
- **Заказы → «Загрузить реестр Казпочты»**: выберите PDF-реестр (он читается прямо в браузере, на сервер уходят только номера треков, имена, телефоны и адреса для сопоставления; в базе реестр не хранится). CRM найдёт заказ по телефону (последние 10 цифр), иначе по имени и городу; ненайденные посылки можно привязать вручную или пропустить. Кнопка «Отметить отправленными» ставит статус «Отправлен», службу «Казпочта», трек и списывает остаток со склада (ровно один раз). Потом список «Разослать треки»: кнопка «Отправить трек в WhatsApp» копирует текст сообщения и открывает чат клиента — вставьте текст и отправьте; в заказе появляется «трек отправлен ✓».
- **Меню → Настройки**: «Шаблон сообщения с трек-номером» (подстановки {имя}, {трек}, {ссылка}) и «Ссылка для отслеживания» (должна начинаться с https:// и содержать {трек}; по умолчанию https://post.kz/services/postal/{трек}). Рядом с треком в заказе показывается ссылка «Отследить».
- Заявки из воронки Threads (комментарий «пар») появляются в «Заказах» сами, статус «Новый».
- После 10 неверных паролей подряд вход для этой почты закрывается на 15 минут.

## Для разработчика

- Акции: миграция `0009_promo.sql` (`orders.promo`, `paid_qty`, `gift_qty`; `qty` остаётся общим отправленным количеством). Сервер сам считает подарок и `qty` (`resolveQty` в `src/worker.js`); при акции присланный клиентом `qty` игнорируется. Расчёты прибыли и акций — `public/promo.js` (работает и в браузере, и в Node), тесты `test/promo.test.js`. Расходы товара лежат в `finance/<productId>`: `buy, other, ship, pack, feePct, extras[{name, amount, per:'unit'|'parcel'}]`.

- `src/worker.js` — API и раздача страницы; `public/` — страница (JS и CSS в файлах, инлайн-скриптов нет из-за CSP); `migrations/` — схема D1.
- Машинные эндпоинты (заголовок `X-Api-Key`): `POST /api/hooks/lead`, `/api/hooks/content-sync`, `/api/hooks/content-status`, `/api/hooks/bot-stats`, `/api/bootstrap`.
- Клиенты на Python: `tools/crm/client.py`, `tools/crm/sync_content.py`. Адрес — `CRM_URL` или `crm/url.txt`; без адреса или `CRM_API_KEY` они ничего не делают.
- Реестр Казпочты: `public/kazpost.js` (разбор текста реестра, `parseKazpost`) + pdf.js 4.10.38 (legacy-сборка, Apache-2.0, лицензия рядом) в `public/vendor/pdfjs/`; API `POST /api/kazpost/preview` и `/api/kazpost/apply` (админ и менеджер), `POST /api/orders/:id/track-sent`; миграция `0002_kazpost.sql` (колонка `orders.track_sent_at`).
- Тесты разбора: `node --test test/kazpost.test.js` (синтетический реестр в `test/fixtures/`, сгенерирован `test/make-kazpost-fixture.js`; реальный реестр в репозиторий не кладём).
- Локальный запуск: `npm i wrangler@3.114.17`, `npx wrangler d1 migrations apply bikas-crm --local`, `npx wrangler dev --local --var CRM_API_KEY:test`.
- WhatsApp-ящик (миграция `0003_inbox.sql`: `wa_numbers`, `target_texts`, `contacts`, `messages`, колонки `orders.traffic`, `orders.target_code`). Чистая логика: `src/source.js` (`detectSource`: код `(A3)` / `#A3` / `код A3` → текст цели или 80 % слов → рекламный `referral` → органика), `src/wa.js` (`parseWebhook` для Cloud API: messages, `smb_message_echoes`, `history`, статусы; `normalizeInboxEvents` для коннектора). Тесты: `node --test test/*.test.js` (на Node 22 каталог `test/` одним аргументом не принимается, указывайте файлы или маску).
- Входящие события (одна функция `ingestEvents`, два входа): `GET/POST /api/hooks/whatsapp` (Meta; проверка `hub.verify_token` = `WA_VERIFY_TOKEN`, подпись `X-Hub-Signature-256` по `WA_APP_SECRET`, без секрета 503) и `POST /api/hooks/inbox` (заголовок `X-Api-Key` = `CRM_API_KEY`, тело `{events:[…]}` в нормализованном виде: `kind` message/echo/history/status, `numberPhone` (цифры бизнес-номера), `waId`, `profileName`, `direction` (для history), `msg:{id, ts, type, body, mediaId|mediaUrl, mime, caption, referral}`, для status `id`, `status`, `ts`). Неизвестный номер создаётся сам (не «текущий»); сообщения идемпотентны по `ext_msg_id`; источник определяется один раз по первому сообщению (история → «Старый»), ручной выбор (`source_manual`) не перезаписывается.
- Отправка: `POST /api/chats/:id/send` идёт с номера, на который писал клиент, через `sendVia`: Cloud API (есть `phone_number_id` и `WA_TOKEN`), иначе `CONNECTOR_URL/send` (`X-Api-Key: CONNECTOR_KEY`, JSON `{numberPhone, to, type:'text', text}`, ответ `{id}`), иначе 503. Заблокированный/выключенный номер → 409; окно 24 ч (только Cloud API) → 409 с `code: 'window'`.
- API чатов (админ и менеджер): `GET /api/chats?q=&filter=unread|target|organic` (`?count=1` — только счётчик), `GET /api/chats/:id` (помечает прочитанным), `POST /api/chats/:id/send|source|order`, `GET /api/media/:messageId` (прокси вложений; для `mediaUrl` коннектора только хосты из `CONNECTOR_MEDIA_HOSTS`, иначе 400; поддерживает Range). Админ пишет, менеджер читает: `/api/wa-numbers` (+ `POST /:id/current` — атомарно единственный текущий) и `/api/targets`.
- Публичные ссылки без входа: `GET /wa` → 302 на `https://wa.me/<текущий номер>`, `GET /wa/<код>` → то же с `?text=` из активного таргет-текста (считает клики); нет текущего номера → страница «Номер временно недоступен». Ответы `Cache-Control: no-store`.
- QR-коннектор (`connector/`, миграция `0004_connector.sql`: таблицы `connector` (одна строка), `outbox`, `media`, колонка `messages.media_ref`, статус сообщения `queued`; таблица `messages` пересоздаётся). API для коннектора, заголовок `Authorization: Bearer <ключ>` (в базе только SHA-256, сравнение с постоянным временем, без сессии и CSRF): `POST /api/connector/state` (`{state: connecting|qr|open|closed|logged_out|banned, qr, phone, name, version}`; `open` создаёт номер `connection='qr'`, делает его текущим, если текущего нет или после «Переподключить»; остальные QR-номера получают `connection=''`), `POST /api/connector/events` (тело как у `/api/hooks/inbox`, плюс `msg.mediaRef`; общий `ingestEvents`), `POST /api/connector/media` (`{mime, data: base64}` ≤ 1,5 МБ, ответ `{id}`), `GET /api/connector/media/:id`, `GET /api/connector/outbox?ready=0|1` (атомарно переводит `queued` в `sending`, не больше 5; `command:'relink'` отдаётся один раз; `sending` старше 2 минут возвращается в очередь, после 3 попыток `failed`; в очереди дольше 6 часов тоже `failed`; сообщения для прежнего номера не выдаются), `POST /api/connector/ack` (`{id, ok, extMsgId|error}`).
- Для админа: `GET /api/wa-server`, `POST /api/wa-server/key` (ключ 32 байта, ответ со скриптом; шаблон один на всех: `connector/cloud-init.template.sh`, в Worker попадает сгенерированным `src/connector_script.js`: после правки шаблона выполните `node scripts/gen-cloud-init.js`, тест сравнивает файлы), `POST /api/wa-server/relink`. Отправка в чат через такой номер: `sendChatMessage` / `POST /api/chats/:id/voice|image` (`{data: base64, mime, caption}`) кладут запись в `outbox`; пути Cloud API и `CONNECTOR_URL` работают как раньше (если ключ коннектора не создан или номер другой). Файлы в D1 хранятся 120 дней (чистка в утреннем cron). `/api/media/:messageId` отдаёт и файлы из D1 (Range поддерживается). CSP: `img-src 'self' data: blob:`, `media-src 'self' blob:`; `Permissions-Policy: microphone=(self)`.
- Тесты Worker на локальной D1: `test/connector.test.js` (нужен `miniflare`, ставится вместе с wrangler; без него пропускаются).
- Секреты Worker (необязательные): `WA_TOKEN`, `WA_APP_SECRET`, `WA_VERIFY_TOKEN`, `CONNECTOR_URL`, `CONNECTOR_KEY`, `CONNECTOR_MEDIA_HOSTS`; ставит деплой, только если значение не пустое.
- Локальная проверка: `npx wrangler dev --local --var CRM_API_KEY:test --var WA_APP_SECRET:x --var WA_VERIFY_TOKEN:y`.
