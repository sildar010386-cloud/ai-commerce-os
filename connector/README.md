# Подключение WhatsApp (коннектор)

Маленькая программа на бесплатном сервере или на вашем Windows-ноутбуке. Она держит ваш номер WhatsApp как «Связанное устройство» (как WhatsApp Web), передаёт сообщения в CRM и отправляет ответы, которые вы пишете в CRM (текст, голосовые, фото). Входящих портов у сервера нет: он сам обращается к CRM по HTTPS. Телефон продолжает работать как обычно.

## Как установить на сервер (Linux)

1. CRM → Меню → Настройки → «Подключение WhatsApp» → **Создать ключ подключения**. Скрипт показывается один раз и содержит секретный ключ: никому его не отправляйте.
2. Создайте бесплатный сервер с Ubuntu 22.04 или 24.04 (1 ГБ памяти достаточно).
   - **Google Cloud** (e2-micro, регион us-central1): Compute Engine → ваша машина → Изменить → «Автоматизация» → «Скрипт запуска» (Startup script) → вставьте скрипт → Сохранить → перезапустите машину.
   - **Oracle Cloud**: Create instance → Show advanced options → Management → Initialization script → вставьте скрипт. Oracle отключает «простаивающие» бесплатные серверы, поэтому после установки выполните на сервере `sudo sed -i 's/^KEEP_BUSY=.*/KEEP_BUSY=1/' /etc/bikas-connector.env && sudo systemctl restart bikas-busy` (или поставьте `KEEP_BUSY=1` в скрипте до вставки). Тогда включится фоновая нагрузка с низким приоритетом (около 25 % одного ядра, `nice 19`), которая не мешает основной программе.
3. Подождите 3–5 минут. В CRM → Настройки → «Подключение WhatsApp» появится «На связи» и QR-код.
4. На телефоне: WhatsApp Business → ⋮ → Связанные устройства → Привязать устройство → отсканируйте QR-код с экрана CRM.

Скрипт безопасно запускается при каждой загрузке сервера: он только проверяет, что программа работает, и не трогает сессию WhatsApp.

## Как проверить, что работает

- В CRM → Настройки → «Подключение WhatsApp»: «На связи», номер и версия.
- Напишите на номер с другого телефона: чат появится в CRM за несколько секунд. Ответьте из CRM: у сообщения будет «в очереди», затем «отправлено», «доставлено», «прочитано».
- «Нет связи N мин»: сервер выключен или без интернета. Сообщения из CRM не пропадают: они уйдут, когда сервер вернётся (но не позже чем через 6 часов).

## Номер заблокировали: как переподключить

CRM → Настройки → «Подключение WhatsApp» → **Переподключить на другой номер** → подтвердите → через минуту появится QR-код → отсканируйте его другим телефоном. Когда новый номер подключится, все ссылки `/wa` и `/wa/<код>` сами переключатся на него. Старые сообщения остаются в CRM. Одновременно подключён один номер.

## Windows (ноутбук)

Подходит, если сервера нет: подключение работает на вашем ноутбуке, пока он включён. Права администратора не нужны, всё ставится в папку вашего пользователя `%LOCALAPPDATA%\BikasWhatsApp`.

1. CRM → Меню → Настройки → «Подключение WhatsApp» → блок «На этом компьютере (Windows)» → **Скачать установщик для Windows**. Кнопка создаёт новый ключ (прежний сразу перестаёт работать; перед этим CRM спрашивает подтверждение) и скачивает файл `BikasWhatsApp-setup.cmd` с вшитым ключом. Файл секретный: никому его не отправляйте.
2. Откройте файл двойным щелчком. Если Windows покажет «Windows защитила ваш компьютер», нажмите «Подробнее» → «Выполнить в любом случае». Браузер тоже может спросить, оставить ли файл.
3. В чёрном окне идут шаги на русском (проверка связи, Node.js, программа, автозапуск, запуск). В конце: «Готово. Откройте CRM → Настройки → Подключение WhatsApp и отсканируйте QR-код».
4. Отсканируйте QR-код телефоном (WhatsApp Business → ⋮ → Связанные устройства → Привязать устройство).

**Важно про выключенный ноутбук.** Пока ноутбук включён и есть интернет, сообщения приходят в CRM, а ответы из CRM уходят клиентам. Ночью, когда он выключен, WhatsApp сам хранит входящие для связанных устройств и отдаёт их, когда программа снова подключится. Ответы, написанные из CRM в это время, ждут до 6 часов, потом помечаются ошибкой. Если ноутбук не включали много дней (две недели и больше), WhatsApp может отвязать устройство: тогда в CRM снова появится QR-код.

### Что установщик делает

- Скачивает портативный Node.js 20 (та же версия, что в `install.sh`; zip для win-x64 с nodejs.org, контрольная сумма SHA256 сверяется с `SHASUMS256.txt`).
- Скачивает **только папку `connector/`** из ветки на GitHub (а не архив всей ветки: в репозитории есть видео и картинки, архив весит больше гигабайта). Берётся последний коммит, менявший `connector/`, список файлов из git-дерева, каждый файл с `raw.githubusercontent.com` на этом коммите; хеш каждого файла сверяется с git. Для этого установщик сначала скачивает один файл `connector/src/update.js` и запускает его.
- Ставит зависимости `npm ci --omit=dev` портативным npm. Одна зависимость Baileys (libsignal) подтягивается через git; если git на компьютере нет (на ноутбуке его обычно нет), она берётся как архив с codeload.github.com с тем же коммитом (`overrides` в `package.json`, делается только на копии в папке установки).
- Пишет `config.env` (адрес CRM и ключ); доступ к файлу ограничен текущим пользователем (`icacls`).
- Создаёт автозапуск при входе в Windows: запланированная задача `BikasWhatsApp` (при входе пользователя, перезапуск при сбое); если на неё нет прав, маленький скрытый `.vbs` в папке «Автозагрузка». Программа работает без окна консоли.
- Запускает подключение сразу и создаёт в папке установки `Остановить.cmd`, `Запустить.cmd`, `Удалить.cmd` (удаление спрашивает подтверждение, словом «ДА») и журнал `connector.log` (ротация: до 1 МБ и 2 старых файла).

Повторный запуск `BikasWhatsApp-setup.cmd` = обновление или починка: код и зависимости ставятся заново, ключ и автозапуск перезаписываются, папка `data` (вход в WhatsApp, очередь событий) не трогается.

### Как это устроено

Папка установки: `node\` (портативный Node.js), `app\` (код), `data\` (`auth\`, `queue.jsonl`, `lids.json`), `config.env`, `connector.log`, `launcher.vbs`, `tools.ps1`, `version.txt`.

- `launcher.vbs` запускает `node app\src\supervisor.js` скрыто и, если процесс завершился, поднимает его снова через 10 секунд (код выхода 99 значит «не перезапускать»: уже запущена другая копия).
- `src/supervisor.js` запускает `src/index.js`, перезапускает при падении (пауза растёт до минуты при частых сбоях), пишет вывод в `connector.log`. Одна копия на компьютер: замок это локальный порт `47653` (`BIKAS_LOCK_PORT`).
- **Автообновление** (`BIKAS_AUTOUPDATE=1` в `config.env`): через 45 секунд после запуска и затем каждые 24 часа супервизор сравнивает последний коммит ветки для `connector/` (`https://api.github.com/repos/sildar010386-cloud/ai-commerce-os/commits?sha=claude/practical-mendel-vjtsd5&path=connector&per_page=1`) с `version.txt`. Если коммит новее: останавливает подключение, скачивает в `app.new`, ставит зависимости (если `package-lock.json` не менялся, `node_modules` переносится), заменяет `app` и перезапускается. При ошибке остаётся прежняя версия, тот же коммит повторно пробуют не раньше чем через 24 часа.
- **Сон и сеть** (`src/bridge.js`): раз в 15 секунд сторожевой таймер проверяет, не «проспал» ли компьютер (пауза между проверками больше минуты: сокет пересоздаётся сразу), приходят ли кадры от WhatsApp (при открытом соединении раз в ~30 секунд приходит ответ на keep-alive; тишина дольше `WATCHDOG_MINUTES`, по умолчанию 5, значит соединение мёртвое) и не завис ли сокет в состоянии «подключается» (больше 3 минут).
- **Голосовые без ffmpeg.** CRM записывает голос в браузере (WebM/Opus в Chrome) и сразу переупаковывает в Ogg/Opus (`crm/cf/public/ogg.js`, без перекодирования). Коннектор отправляет такой файл как голосовое (ptt) без обработки. ffmpeg нужен только для других форматов и только если он есть (на Linux-сервере); на Windows такое аудио уйдёт обычным аудиофайлом, в журнале будет запись. Браузеры без WebM/Ogg (Safari записывает MP4) тоже отправляют обычным аудио.

### Пути и настройки (переменные окружения)

`BIKAS_HOME` (папка установки; на Windows по умолчанию `%LOCALAPPDATA%\BikasWhatsApp`), `ENV_FILE` (по умолчанию `<BIKAS_HOME>\config.env`, на Linux `/etc/bikas-connector.env`), `STATE_DIR` (`<BIKAS_HOME>\data`, на Linux `/var/lib/bikas-connector`), `AUTH_DIR` (`<STATE_DIR>\auth`), `QUEUE_FILE` (`<STATE_DIR>\queue.jsonl`), `LOG_FILE` (`<BIKAS_HOME>\connector.log`, пишет супервизор), `WATCHDOG_MINUTES`, `BIKAS_AUTOUPDATE`, `BIKAS_BRANCH`. Реальное окружение сильнее файла `config.env`. Фоновая нагрузка `KEEP_BUSY` на Windows не используется.

### Если что-то не получилось

- В окне установщика красная строка «Не получилось: …»: проверьте интернет и запустите файл ещё раз; если ключ устарел (создали новый), скачайте установщик в CRM заново.
- Статус в CRM «Нет связи»: ноутбук выключен или спит; откройте `Запустить.cmd` и посмотрите `connector.log`.
- Чтобы убрать подключение: `Удалить.cmd`, затем на телефоне WhatsApp → Связанные устройства → это устройство → Выйти.
- Установщик не проверялся на настоящей Windows: разработка шла на Linux (разбор PowerShell и все не зависящие от Windows части проверены, см. тесты). Первый запуск стоит сделать при владельце ноутбука и смотреть на окно.

## Для администратора сервера

- Статус и журнал: `systemctl status bikas-connector`, `journalctl -u bikas-connector -f`, `/var/log/bikas-install.log`.
- Настройки: `/etc/bikas-connector.env` (`CRM_URL`, `CONNECTOR_TOKEN`, `KEEP_BUSY`; по умолчанию `KEEP_BUSY=0`). Сессия WhatsApp: `/var/lib/bikas-connector/auth`, очередь недоставленных событий: `/var/lib/bikas-connector/queue.jsonl`.
- Каждый день сервер сам забирает обновления из ветки `claude/practical-mendel-vjtsd5` и перезапускает программу, только если изменилась папка `connector/`.
- Логика: `src/map.js` (преобразование сообщений Baileys в события CRM, тесты `npm test`), `src/bridge.js` (сокет, очередь отправки, переподключения), `src/crm.js` (запросы с повторами), `src/queue.js` (очередь на диске), `src/busy.js` (фоновая нагрузка).
- Вложения до 1,5 МБ (фото, голосовые, стикеры, небольшие файлы) загружаются в CRM; большие и видео остаются на телефоне, в чате пишется заметка. История берётся за последние 180 дней, не более 5000 сообщений.
