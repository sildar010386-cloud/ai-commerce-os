# Публикация: проверенный порядок (правила из реальных ошибок)

**Общие правила подписи (владелец 2026-10-01):** не больше 5 хэштегов; карусели TikTok — без описания (пустые title/description), CTA на последнем слайде.

Любая публикация — только после «да» владельца на этот конкретный пост (текст, картинки/видео, подпись).

## Threads — ветка из N постов

Скрипт: `tools/threads/publish_thread.py CODE SHA` (черновик в `content/threads/CODE/README.md`, разделы «## Пост N — `картинки.jpg`»).

1. Картинки закоммитить и запушить; ссылки — `raw.githubusercontent.com/.../<SHA коммита>/...` (проверить, что отвечают 200).
2. Первый пост — обычный; **каждый следующий — ответом на предыдущий, параметр `reply_to_id`** (не `reply_to_message_id`: его Threads молча игнорирует и публикует отдельный пост — ошибка T-01, 2026-09-30).
3. После каждого ответа скрипт проверяет `is_reply` и `replied_to` = предыдущий пост; если нет — останавливается.
4. После публикации: `published.json` (ID всех постов), проверить цепочку ещё раз, статистика через 24 ч.
5. Удалять посты через API нельзя (нет права `threads_delete`) — при ошибке сообщить владельцу, он удаляет вручную. Продолжить цепочку: `publish_thread.py CODE SHA PARENT_ID START_N`.

## Instagram — Reels

Скрипт: `tools/instagram/publish_reel.py VIDEO_URL CAPTION.txt OUT.json`.

1. Загрузка файла напрямую (`upload_type=resumable`) для нашего токена (вход через Instagram) **не работает** — нужна публичная ссылка `video_url`. Одобренный MP4 коммитим в `content/reels/CODE/` и берём ссылку на коммит.
2. Файл должен быть ровно тем, что одобрил владелец (сверить время/хэш).
3. Подпись — из `README.md` ролика, без изменений.
4. Музыку из библиотеки Instagram через API добавить нельзя — музыка вшивается в файл при сборке (CONTENT_PLAYBOOK §12).
5. После публикации: проверить ролик и подпись через API, записать `published.json`.

## Instagram — Stories

Тот же скрипт с `--story`: `media_type=STORIES`, подпись не используется. Видео 9:16, до 60 сек. Ссылки/стикеры через API не добавляются. Нижнюю часть кадра в Stories перекрывает строка ответа — важный текст держать выше.

## Связка Reels → Stories

**Решение владельца 2026-09-30:** после публикации одобренного Reels тот же ролик **сразу публикуется в Stories без отдельного вопроса** (одобрение Reels = одобрение его Stories). Первый раз: REEL-01 с музыкой, 2026-09-30.

## TikTok — черновик во «Входящие»

Скрипт: `python3 tools/tiktok/tt.py draft файл.mp4` (без проверки приложения TikTok; до 5 черновиков в сутки). Владелец публикует черновик в приложении сам.

1. Файл загружается на отдельный сервер TikTok (`open-upload-sg.tiktokapis.com`, адрес выдаёт API). Он должен быть в разрешённых доменах сети облачной среды, иначе `Tunnel connection failed: 403` (ошибка TT-01, 2026-10-01). Лучше разрешить `*.tiktokapis.com`.
2. Подпись через черновик не передаётся — готовый текст с хэштегами присылаем владельцу в чат, он вставляет его в TikTok.
3. После публикации: найти ролик в `tt.py videos`, записать `tiktok_published.json` в папку ролика.

## TikTok — карусель (фото) из ветки Threads

1. `python3 tools/tiktok/carousel.py T-NN` → слайды в `content/threads/T-NN/carousel/`; подпись `content/threads/T-NN/tiktok_caption.txt` (1-я строка — заголовок до 90 символов, дальше — описание).
2. Слайды скопировать в ветку сайта `claude/ai-ecommerce-automation-3n1lgz`, папка `docs/tiktok/media/T-NN/` (разрешение владельца 2026-10-01), дождаться «pages build and deployment».
3. `python3 tools/tiktok/tt.py photos T-NN content/threads/T-NN/tiktok_caption.txt` → черновик с подписью; владелец добавляет музыку и публикует. Первый раз: T-03, 2026-10-01.

**Ошибка TT-02 (2026-10-01):** фото-черновики (карусели) через API доходят до статуса `SEND_TO_USER_INBOX`, но уведомление в приложении у владельца **не появляется** (две попытки T-03). Видео-черновики приходят нормально. Пока карусели TikTok публикуются вручную: картинки и подпись — владельцу в чат.
Позже в тот же день (REEL-02, 07:48 UTC) не пришёл и **видео**-черновик, хотя статус тоже `SEND_TO_USER_INBOX`. Вечером 2026-09-30 (REEL-01) видео-черновик пришёл. Токен, аккаунт и права не менялись (saved_at 2026-09-30 22:05 UTC), утренняя статистика только читала данные. Причина на стороне TikTok не установлена. **Уточнение:** уведомление о карусели T-03 (отправлена ~07:25 UTC) пришло владельцу примерно через 2 часа — черновики приходят **с задержкой**, а не теряются. Поэтому: не отправлять черновик повторно (второй T-03 пришёл бы дублем); если владелец уже загрузил ролик вручную, пришедший позже черновик не публиковать — один файл в TikTok дважды нельзя. Пока не пришло — владелец загружает присланный в чат MP4 в TikTok вручную.

**Ошибка TT-03 (2026-10-01):** прямая публикация (`tt.py photos ... --direct`, `DIRECT_POST` + `SELF_ONLY`) у непроверенного приложения отклоняется: `unaudited_client_can_only_post_to_private_accounts` — TikTok разрешает её только в **закрытые аккаунты** целиком, а не «Только я» для отдельного поста. Для bikas.home (бизнес-аккаунт) не подходит. Остаются: черновик во «Входящие» (с задержкой) или ручная загрузка файлов из чата; полная автопубликация — только через проверенный сервис-посредник (решение владельца отложено).

**Ошибка TT-04 (2026-10-01):** `spam_risk_too_many_pending_share` — у TikTok лимит неразобранных черновиков (около 5). Пока владелец не опубликует/удалит пришедшие черновики, новые не принимаются. Не больше 4–5 черновиков в сутки; при отказе — слайды/видео владельцу в бот для ручной загрузки.

**Ошибка T-02 (2026-10-01, Threads, T-09):** «Media Not Found» на **третьем** посте; посты 1 и 2 уже вышли. Вывод скрипта был обрезан (`tail -1`), а `me/threads` показывает только главные посты, не ответы — поэтому пост 2 опубликован повторно, и пост 3 ушёл под дубль; владелец видел ветку без третьего поста. Правила: **не обрезать вывод публикации**; при сбое смотреть `content/threads/CODE/published.json` (скрипт теперь пишет его после каждого поста, `complete: false`) и `GET /{root}/conversation` (ответы); продолжать с последнего реально вышедшего поста. Удалить лишнее через API нельзя — просить владельца.
