# Подключение соцсетей к Claude

Всё бесплатно, только официальные API. Пароли и токены в чат не отправляем: токен владелец вставляет в настройки облачной среды Claude, Claude читает его из переменной окружения.

Порядок: Instagram → Threads → TikTok.

## Что будет возможно после подключения

| | Instagram | Threads | TikTok |
|---|---|---|---|
| Статистика каждого ролика/поста | да: просмотры, охват, лайки, комментарии, сохранения, репосты, среднее время просмотра | да: просмотры, лайки, ответы, репосты, цитаты | да: просмотры, лайки, комментарии, репосты |
| Статистика профиля | да: охват, подписчики, демография | да: подписчики, демография | да: подписчики, лайки |
| Публикация | Reels и посты, после одобрения владельца | посты и ветки | только после проверки приложения TikTok; до этого публикует владелец вручную |
| Комментарии | чтение и ответы | чтение и ответы | чтение |
| Шапка профиля (фото, имя, описание, ссылка) | **нет**: API не даёт. Claude пишет тексты, владелец вставляет | **нет** | **нет** |

Ограничения:
- Графика удержания по секундам нет ни в одном API. Для оценки хука: среднее время просмотра ÷ длина ролика; при необходимости — скриншот удержания из приложения.
- Reels через API публикуются без трендовой музыки из библиотеки Instagram (для роликов с озвучкой не важно).
- Токен Instagram и Threads живёт 60 дней. Claude заранее напомнит обновить.
- Claude работает в сессиях, не круглосуточно. Сбор статистики по расписанию — отдельная настройка (ежедневная сессия), позже.

## Шаг 0. Сеть среды (один раз для всех трёх)

Меню облачной среды в заголовке сессии → **Edit** → **Network access** → добавить в разрешённые домены:

```
graph.instagram.com
rupload.facebook.com
graph.facebook.com
graph.threads.net
open.tiktokapis.com
```

## Instagram

1. **Профессиональный аккаунт.** Instagram → Профиль → ☰ → «Настройки и конфиденциальность» → «Тип аккаунта и инструменты» → «Переключиться на профессиональный аккаунт» → «Бизнес» → категория (например, «Товары для дома»). Если аккаунт уже бизнес или автор — пропустить.
2. **Кабинет разработчика.** С компьютера открыть developers.facebook.com → войти через Facebook → «Начать» / зарегистрироваться как разработчик (подтверждение по телефону или почте).
3. **Приложение.** «Мои приложения» → «Создать приложение» → название `AI Commerce OS` → вариант использования **«Управление сообщениями и контентом в Instagram»** → тип «Бизнес» (если спросит) → создать.
4. **Токен.** В приложении: «Варианты использования» → Instagram → «Настроить» → **«Настройка API со входом через Instagram»** → раздел **«Сгенерировать маркеры доступа»** → «Добавить аккаунт» → войти в свой Instagram → разрешить все запрошенные права. Если Instagram попросит принять приглашение тестировщика: Instagram → Настройки → «Приложения и сайты» → «Приглашения тестировщиков» → принять. Затем в строке аккаунта нажать **«Сгенерировать маркер»** → скопировать.
5. **Сохранить токен в среде** (не в чат): меню среды → **Edit** → переменные окружения → добавить `IG_ACCESS_TOKEN=<токен>` → сохранить.
6. **Новая сессия** (настройки среды применяются к новой сессии) → написать Claude «Instagram подключён». Claude проверит профиль, список роликов и статистику.

Права, которые нужны: `instagram_business_basic`, `instagram_business_content_publish`, `instagram_business_manage_insights`, `instagram_business_manage_comments`.

## Threads

0. **Профиль Threads у bikas.home.** Приложение Threads → войти через Instagram bikas.home. Если профиль уже есть — пропустить.
1. **Отдельное приложение** (Threads не добавляется к приложению Instagram): developers.facebook.com → «Мои приложения» → «Создать приложение» → название `AI Commerce Threads` → вариант использования **«Доступ к Threads API»** → создать (бизнес-портфолио не нужно).
2. **Права.** «Варианты использования» → Threads API → «Настроить» → «Разрешения»: добавить `threads_basic`, `threads_content_publish`, `threads_manage_insights`, `threads_read_replies`, `threads_manage_replies`.
3. **Тестировщик.** Слева «Роли приложения» → «Роли» → «Добавить людей» → роль **«Тестировщик Threads»** → имя `bikas.home` → «Добавить».
4. **Принять приглашение.** В браузере threads.com → войти как bikas.home → Настройки → «Аккаунт» → «Разрешения для сайтов» → «Приглашения» → «Принять». (С телефона тот же путь в приложении Threads.)
5. **Токен.** «Варианты использования» → Threads API → «Настройки» → **«Генератор маркеров доступа пользователя»** → рядом с bikas.home «Сгенерировать маркер» → войти, разрешить → скопировать.
6. **Сохранить в среде** (не в чат): меню среды → Edit → Environment variables → новая строка `THREADS_ACCESS_TOKEN=<токен>` → Save. Домен `graph.threads.net` уже в списке.
7. Написать Claude «Threads подключён».

Подсказки (из опыта подключения 2026-09-30):
- Приглашение тестировщика принимается **только в мобильном приложении** Threads (Настройки → Аккаунт → Разрешения для сайтов → Приглашения); на сайте threads.com этой вкладки нет.
- Ошибка генератора «The user has not accepted the invite» после принятия приглашения — подождать 15–30 минут или попробовать **окно инкогнито** (Ctrl+Shift+N): войти на threads.com под bikas.home, затем в кабинет разработчика, нажать генератор оттуда.

## TikTok

Сайт приложения (GitHub Pages из папки `docs/` основной ветки): `https://sildar010386-cloud.github.io/ai-commerce-os/` — `index.html`, `privacy.html`, `terms.html`, страница возврата `tiktok/callback.html`, иконка `docs/assets/app-icon.png`.

1. **GitHub Pages** (один раз): репозиторий `ai-commerce-os` → Settings → Pages → Source «Deploy from a branch» → ветка `claude/ai-ecommerce-automation-3n1lgz`, папка `/docs` → Save. Через 1–2 минуты сайт открывается по адресу выше.
2. **Кабинет разработчика:** developers.tiktok.com → Log in (аккаунт TikTok bikas.home) → зарегистрироваться как разработчик.
2a. **Подтверждение сайта:** URL properties → URL prefix `https://sildar010386-cloud.github.io/ai-commerce-os/` → TikTok даёт файл `tiktok….txt` → он лежит в `docs/` (уже добавлен: `docs/tiktokEh6dGTC288Pulsi6JD0zYQxQhbMeaxyz.txt`) → Verify.
3. **Приложение:** Manage apps → Connect an app (тип «Individual») → название `Bikas Home Publisher`, иконка `app-icon.png`, категория, описание; Terms of Service URL = `.../terms.html`, Privacy Policy URL = `.../privacy.html`; платформа Web, Website URL = адрес сайта.
4. **Продукты:** добавить Login Kit (Redirect URI = `.../tiktok/callback.html`) и Content Posting API. Права (scopes): `user.info.basic`, `user.info.profile`, `user.info.stats`, `video.list`, `video.upload` (добавляется сам с Content Posting API), `video.publish` (появляется при включении **Direct Post** — владелец включил: цель — полная автопубликация).
5. **Sandbox** (вкладка рядом с Production; «Submit for review» не нажимать): → создать → Target users → добавить свой аккаунт TikTok. В песочнице проверка TikTok не нужна.
6. **Ключи в среду (не в чат):** Client key и Client secret — из вкладки **Sandbox** → Edit → Environment variables: `TIKTOK_CLIENT_KEY=...`, `TIKTOK_CLIENT_SECRET=...`.
7. **Вход:** Claude присылает ссылку входа → владелец разрешает доступ → страница `callback.html` показывает код → код в среду как `TIKTOK_AUTH_CODE` → Claude обменивает его на токены.

Сохранение черновика Production требует всех обязательных полей: иконка (`https://sildar010386-cloud.github.io/ai-commerce-os/assets/app-icon.png`), текст для App review (готовый текст — `docs/tiktok/app_review_text.txt`), демо-видео. Настоящее демо-видео снимается после того, как песочница заработает; до этого для сохранения черновика можно временно загрузить любой ролик и заменить перед «Submit for review».

Ограничения: без проверки приложения TikTok (audit) прямые публикации через API только приватные (видны только владельцу). Для публичной автопубликации: песочница → проверка → запись демо-видео → Submit for review → после одобрения автопубликация публичная.
